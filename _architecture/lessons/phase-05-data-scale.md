# Phase 5: Data & Scale

Data is where architectures live or die: it's the heaviest thing to move, the
hardest to change, and usually the first thing to break under growth. This phase
covers choosing the right store for an access pattern (polyglot persistence), two
powerful and frequently-misapplied patterns (event sourcing and CQRS), caching as
the sharpest double-edged sword in performance work, and the mechanics of scaling
data past a single database — replication, partitioning, and sharding — with the
consistency taxes each one charges.
